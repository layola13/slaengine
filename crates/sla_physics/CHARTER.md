## 3. 分层

物理座 = 两层：

1. **常规解算层**：刚体动力学、宽相/窄相、约束求解、休眠/岛屿——普通
   物理引擎的本职，架构学参照（见 §7）。
2. **分析预演层**（自研差异化，开源覆盖稀薄）：以当前状态为种子超前
   推演——扫掠式连续求交直接解 time-of-impact（TOI）、按预计事件时刻
   排序的事件驱动推进、撞后全过程与连锁一并算出，输出**带时间戳的预测
   事件流**供预警与决策层消费。

应用域（已定案两个）：

- **自动驾驶预警**（用户原话场景）：本车与他方运动体未碰之前即知将撞
  与撞后全过程，预警与规避的时间窗口来自预演时域（秒级，非帧级）。
- **实时联网 FPS**：客户端预测 = 本地分支按自身输入剧本先行推演、服务
  器权威状态到达时对账修正（即 will 分支的修订/坍缩）；回滚式联机
  （迟到输入以修正剧本重推）与分支模型同构；hitscan/投射物命中判定
  本质是扫掠 TOI 求交；远端玩家快照间外推 = 名义剧本推演。**边界**：
  兴趣管理、带宽、反作弊权威属网络层，不归物理座；物理/预演层供的是
  确定性预测 + 扫掠命中求解两件。

## 4. 底层契约（步进与外力）

- 步进器签名钉死为 **`step(world, dt, inputs)`**：inputs 为一等数据
  （力/力矩/控制量按参与体给），不藏回调、不藏用户指针——这是分支
  可重放的先决条件（参照前提第四条）。
- 每个参与体带**控制面**：油门/刹车/转向等控制量先经执行器映射成力
  （车辆可用简化模型），剧本写控制量、引擎施力，两边都可审计。
- **未来分支的定义 = （状态种子， 外力剧本）**。剧本是外力随时间的
  时间序列数据：恒定 = 匀速外推，阶跃 = 突入加速，斜坡 = 渐进刹车，
  转向角曲线 = 转弯。分支由剧本扰动族生成：名义外推 + 加速/刹车/
  左右避让扰动。
- **同源铁规**：实时仿真与全部预演分支共用同一积分器、同一条施力
  路径；禁止另写一套「预演物理」——防预演与现实漂移，漂移即预警
  不可信。

## 5. 事件谱系（will / on）

普通引擎只有 on（碰撞已发生）与至多 pre（前一帧）两档，被明确判定
为**远远不够**——此为本座的否定基线。本座事件谱系：

- **`will` 事件**：扫掠解出预计相撞后提前触发，携带——预计相撞时刻
  （TTI）、地点、参与体、**所属未来分支 id**、**所属外力剧本**、撞后
  预测。提前量由预演时域决定。
- **`on` 事件**：碰撞实际发生时触发（普通引擎的那档，本座亦有）。
- **will 生命周期**：随每轮滚动重预演被**确认 / 修订 / 撤回**；分支
  消亡，其 will 事件随之撤回；被实现的那条在时刻到达时转为 on 事件。
- 消费侧按分支聚合订阅（最早 TTI、概率加权等口径归消费层裁定，
  不归物理座）。

## 6. 多未来并行与确定性

- 多条候选未来如叠加态并存、并行推演（用户以量子力学多态作比）；
  真实时间推进时实际发生的那条「坍缩」为现实，其余修正或作废。
- 执行形态：原生侧 = 多世界克隆 + goroutine 并行步进（世界值式可
  多开）；@gpu 侧 = 元素形轻推演占车道批量 rollout（重解算不进 GPU
  车道，见 §8）。
- **定点确定性是刚需**：同一种子推演两次必须逐位一致，预演结果
  可复现、可审计；浮点非确定性正是经典联机预测失配/失同步的根源，
  本座以定点算术为底（与 @gpu 小球阶梯的定点逐位口径同源）。

## 7. 参照前提与分工

参照须先过四条前提（预演方向立后增设的筛子）：

1. **确定性**：同状态同输入必得同结果，可复现可审计；
2. **扫掠求交为原生面**：连续碰撞/形状扫掠是一等公民接口，非逐帧
   步进后补检；
3. **状态可廉价克隆与快进**：世界能便宜复制、独立步进、互不干扰
   （多未来分支的前提）；
4. **步进接受数据化的外力/控制输入**：输入是一等数据、非回调注入
   （外力剧本可重放的前提）。

参照分工（只学架构，洁净室实现）：

| 参照 | 席位 | 学什么 | 不学/边界 |
|---|---|---|---|
| **Rapier** | 主位（解算层架构骨架） | 世界值式多开、跨平台确定性设计、原生 CCD、显式施力接口 | 不作运行时依赖（extern 已否决为终局）；浮点确定性级别不及定点审计级 |
| **Jolt** | 求解器蓝本 | 约束求解质量、多线程岛屿调度 | 确定性仅同平台内成立；世界克隆形态不如 Rapier 自然 |
| **Box2D v3** | C 席位形态 + 2D | C 实现形态、图着色并行求解（与 @gpu 车道同构）、子步进 | 2D 域为主，3D 架构不从此出 |
| **PhysX** | 仅 GPU 管线切分参照 | GPU 管线如何切分 | 黑盒管线过不了确定性审计关，不作结构参照 |
| **Bullet** | Blender 场景语义对表 | Blender 自带刚体/Armory 的场景语义对应关系 | 不作架构参照 |

许可：Rapier = Apache-2.0，Jolt = MIT，Box2D = MIT，PhysX = BSD-3，
Bullet = zlib——均与 workspace `MIT OR Apache-2.0` 相容（学架构不引入
代码，无许可传染面）。逐仓吸收点清单见 docs/REFERENCE_SURVEY.md。

## 8. @gpu 应用面

- 物理计算体（粒子积分/空间哈希宽相/逐对窄相/Jacobi 迭代——小球阶梯
  已实证的元素形态）是 `sla_gpu` 座位的消费面之一：以普通 SLA 函数
  书写、由 @gpu 形态发射。物理座提供计算体的语义与数据布局，GPU
  发射机制归 sci/SLA 面（前置：SLA 面 `@gpu fn` 拼写批）。
- **CSG 布尔**列入 @gpu 应用面，形态钉为 **SDF/体素**：布尔在距离场
  上逐点 min/max（天然元素形），SDF 求值与 marching-cubes 提取皆
  元素形；精确网格 B-rep 布尔（鲁棒谓词）不作 GPU 首选面。场景：
  实时关卡编辑/Blender 布尔类工作流（内嵌 player 语境）。
- 明确不进 @gpu：ECS 调度与系统逻辑、逐帧小规模逻辑、分叉遍历
  （BVH 类，候发射器任务化形态成熟）。
