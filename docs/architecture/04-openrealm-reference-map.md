## 4.0 使用纪律（红线，先于映射表）

[R2-改 2] 本节按双参考结构重写。**不变的条款先行**（与基稿
逐条对照见 IMPACT §0）：

1. **行为真值的裁决权不变**：OpenRealm 是黑盒重写，不是反编译
产物；其行为是仿制与近似，**不是原版规格**。凡与 Warcraft
阶段二逆向规格冲突，以阶段二规格为准（05）。双参考并列，
指的是**参考身份**并列，不指裁决权并列——行为真值只出原版
一路。
2. **不取代码**：参考其组织与行为，不搬其 C 代码进引擎（许可上
MIT 允许，但规格真理与实现独立性要求我们自写；格式解析的
组织方式可学，解析器本体自研并以阶段二规格校准）。
3. 它的成色分层照实登记：玩家可感知面（格式全通、战役可打）
覆盖极高；原版深层逻辑（联机协议、精确数值、AI 细节）缺失
或近似——映射时逐项标注其可信层级，不整表等同。

**升格的条款**（本稿新增身份，自 21:13 定案生效）：

4. **原版魔兽引擎 = 参考引擎**：阶段二逆向获得的原版行为真值
不只是「规格输入」，它定义魔兽引擎目标本身——slaengine 的
魔兽形态要复现的就是这台引擎的行为。阶段二的身份由「规格
供给方」升为参考引擎的真值通道（产出形态仍是规格槽，05）。
5. **OpenRealm = 并列参考**：其身份由「组织参考 + 行为对照清单
来源」升为并列参考——它已被证明可玩的完整行为面（菜单/战役/
单机局/客户端行为全集）是**兼容目标的参照级证据**：05 §5.6
清单判定「完整」时，它的已证行为面是可参照的完成形态。它
仍不产出规格、不参与行为真值裁决（条款 1）；其深层逻辑的
缺失面（联机真形态等）不因升格而变可信（条款 3）。

以裸文件名存储、而建房/地图枚举期望 `Maps/…` 路径，致局域网

**每条 = 一个可复现的现象 + 它在我方架构中的对策落点**。后续
对照工作按此格式增补，落点只许三类：格式层（07）、输入/客户端
域（sla_3d 及未来域）、规格差异登记（05 的差异栏）。清单条目
不得直接升格为我方实现规格——升格须经阶段二规格或我方实测
复核。[R2-改 4 注：双参考升格不改变本条——OpenRealm 的并列参考身份作用于兼容目标的设定（05 §5.6），不作用于规格升格通道；规格通道仍只有阶段二与我方实测两路。]

## 4.3 [R2-改 5] 一等参考域：网络引擎 + 帧同步（新增节）

用户 2026-11-08 21:11 点名、21:13 定案（「联网正常运行」为
魔兽引擎目标本体）：网络引擎与帧同步是双参考中具名的一等
参考域，域内分两面——

- **传输面（Storm 协议）**：局域网发现（UDP 广播）、建房/加入、
直连、地图分发、主机交接。真值通道 = Storm.dll 传输层 +
Game.dll 侧会话/事件机器（SNet 序号面与 SFile 分工见 Warcraf
仓 S1/S7 分析）。
- **同步面（帧同步）**：确定性锁步——输入打包成回合命令、等齐
才推进、命令先同步后执行、回合延迟设置、校验和交换（三层：
子系统校验/网络事件流滚动校验/战争迷雾校验）、失同步的
可信事件处理、确定性随机数同步。真值通道 = Game.dll 同步
机制（Warcraf 仓 S0 帧同步分析 + S1 网络层 + S11 随机数，
1.27a 已有分析级还原）。

域内参考纪律（本节为该域的专门条款，与 §4.0 并行、更严）：

1. **原版侧定真值**：本域的行为真值只许来自阶段二逆向
（Game.dll 同步机制 + Storm 传输，逐版本以 05 的版本矩阵
为准）。
2. **OpenRealm 侧只作对照**：其联机不是真形态——单机局是内嵌
server 形态（§4.1 `server/` 行已登记），无原版锁步协议的
实现面；它在该域可提供的是客户端行为与单机房间流程的对照
（如建房 UI 流程、槽位语义），**不得**作为传输或同步行为的
参照目标，更不得升格为规格（§4.2 通道在本域关闭）。
3. **与引擎核心的接口**：同步面的确定性要求不是魔兽域的局部
特性——它约束引擎的模拟推进形态，定案口径见 01 §1.3 确定
性条（魔兽引擎辖域内的硬约束）与物理座定点确定性口径互引
（IMPACT §5）。
