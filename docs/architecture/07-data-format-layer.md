# 07 数据格式层设计

格式层 = 一组**独立于引擎运行时**的解析/写出库：可被工具、
测试、运行时三方分别消费，自身对上层（ECS、渲染、App）零
依赖。本设计在既有 SAX3D 体系上增补「导入族」一翼，并把
Warcraft 格式族正式编入。

## 7.1 两族

| 族 | 内容 | 真理来源 | 现状 |
|---|---|---|---|
| 原生格式 | SAX3D（引擎自有资产格式：段表+名表+声明索引，SPEC 冻结） | `crates/sax3d/SPEC.md` | 已交付：格式、Zig 工具链、转换器（glTF/Fox 等往返验证） |
| 导入族 | 外来格式的读者群：glTF（经 sax3d 转换器，已通）；**Warcraft 格式族**（MPQ 归档、地图 .w3x/.w3m 及内部件、模型 .mdx/.mdl、贴图 .blp 等，以阶段二枚举为准） | 各格式的规格文档；Warcraft 族以阶段二规格槽（05）为最终真理 | Warcraft 族未开工，本文件定其形态 |

分工原则：**原生格式是引擎资产的唯一运行时真理**；导入族的
产物一律汇入原生声明面或 sla_asset 的中间产物面（PLAN C1），
不许外来格式的数据结构直达 ECS/渲染层。

## 7.2 读者契约（导入族统一面）

导入族每个格式一个读者模块，对上只暴露数据形状契约：

- 归档类（MPQ）：`open(bytes) → 列条目（名/大小/戳）→ 按名读
  条目字节`。条目命名纪律照阶段一教训明文写入契约：**条目名
  以归档内原始路径为准**（`Maps\…` 形），导入侧禁止裸文件名
  化——阶段一局域网列表为空的根因即此，契约层先行堵死。
- 地图类（.w3x/.w3m）：`load(bytes) → 场景描述符`（地形/物件/
  单位放置/玩家/触发器扩展段），形状与 SAX3D scene 声明可
  对照、Warcraft 特有语义进具名扩展段（05 §5.3.3）。
- 模型/贴图类：`load(bytes) → 通道声明/图像声明`，形状对齐
  PLAN C3 的通道布局表与图像描述面。

契约以数据形状冻结，解析内部可换（05 §5.3.1）。读者模块
必须可**脱离引擎单独验收**（对照 OpenRealm `common/` 的
解耦形态，04 §4.1 首行）：给定字节进、描述符出、无全局状态。

## 7.3 Warcraft 导入族的形态约束

1. **运行时形态必需**：阶段一已证明「运行时解析用户提供的
   MPQ」（浏览器 OPFS 本地导入）是真实使用形态，故 Warcraft
   读者不能只有离线转换工具形态，必须有可嵌入运行时的
   SLA 读者形态（离线转换到 SAX3D 的路线可并存，但不能是
   唯一形态）。
2. **规格校准**：读者行为以阶段二规格为最终校准（05 权威
   序）；规格未到部分按 provisional 纪律（05 §5.3.2）。
3. **数据红线**：用户游戏文件永不入仓；开发/验收语料只用
   自制合成资产（05 §5.4）。读者开发期的真实文件验证在仓外
   场地进行，结果只以摘要（条目数/哈希）入仓。
4. **座次未定**：读者群落哪个 crate 是分叉 N1（见架构线
   RESULT.md 分叉清单）：候选为 sla_asset 内设导入组 / 新设
   导入族 crate / sax3d 侧并列转换器组。裁定前本文件只定
   契约与约束，不定座次。

## 7.4 写出面

格式层写出只许两个方向：原生格式写出（转换器/编辑器桥，
已有）与导入族的**回写禁止**——Warcraft 族 v1 只读：不写
MPQ、不写 .w3x（写出涉及原版编辑器语义与兼容风险，是否
开写候主会话在阶段二规格后另行裁定，本集登记为显式不做，
防逐案漂移）。
