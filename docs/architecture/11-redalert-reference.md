本篇编号 11，第三参考（红警）的网络域专节，体例对齐 04；由红警研究线草案经主会话 2026-11-08 审定入仓。

## 定位

- slaengine 终极目标支持三款游戏：魔兽（第一优先）、CS（第二）、红警（第三）。红警在本引擎中的参考辖域为**网络域**（帧同步 / lockstep），与原版魔兽、OpenRealm 双参考并列为第三参考。
- 红警一极的独特价值：它是三极中**唯一有官方源码可直读定真值**的 lockstep 实现——魔兽同范式靠阶段二逆向定真值，CS 是预测-对账的对照范式。红警源码因此承担「lockstep 骨架的校验本」职能：魔兽逆向结论与红警源码形态相合处，证据互强；相异处即两实现的分岔点，逐项登记。
- 裁决序不变：行为真值裁决权仍归原版实测 / 逆向（04 号文档 §4.0 的不变条款不因本节改变）。红警材料只在其自身行为范围内是真值，不覆盖魔兽行为问题。

## 机制要点：lockstep 的最小完备集

红警 1 源码与另两极对照后，帧同步范式的最小完备集定为五件，slaengine 的 G5 / G6 条目按此对表：

1. **命令排入未来节拍执行**：输入延迟是显式协议参数（红警的 MaxAhead：局域网 5 帧 / 互联网 9 帧），不是本地手感设置；参数变更必须以全网时序事件同步生效，并锚定新旧值的生效窗（源码自陈无锚定时存在「脆弱期」会漏命令）。
2. **推进双条件**：本机节拍不得超出最慢对端节拍 + 延迟参数；且每个对端的命令计数对账必须闭合（实收数 >= 对方声称已发数）。前者保命令不越帧，后者把丢包检出做进节拍推进本身。
3. **心跳二合一**：周期心跳同载命令计数与状态校验和（红警 FRAMEINFO），丢包与模拟分歧用同一包检出，零额外带宽。
4. **开局指纹对齐**：开局前以内容指纹（场景 / 规则数据的累积 CRC）互证同图同规则；现代形态升级为握手对象（版本 + 地图 + 规则字节哈希），不合不开局。
5. **确定性随机纪律**：模拟随机走单一确定性流，同步点定义为「随机调用同序、同数」；调用计数指纹作为失同步二分的第一刀进调试面。此件与 01 号文档 §1.3 的确定性条款、物理座的定点确定性要求同向互锁。

## 现代演进三格（原版缺格的补法）

红警 1 的历史形态有三处明确缺格，社区现代实现已给出补法，slaengine 按补法形态预留条目：

- **失同步恢复**：原版检出即判死。rust-alert 的消息面给出恢复三件套——状态摘要（Digest）检出分歧、按 tick 请求（ResyncRequest）、快照续局（ResyncSnapshot）。G6 预留快照重同步条目，快照序列化与 ECS 存档面绑定，实现期定形。
- **互联网化拓扑**：原版是对等全连通 + 外置大厅。vera20k 的形态是「HTTPS 大厅 + 认证 UDP 中继」：中继只做命令排序、准入与认证，客户端保留模拟权威，中继命令流即唯一命令史。此形态与魔兽 Storm 的服务器形态在实现期对照二选一，列为 G5 候选主形。
- **传输韧性**：自适应冗余按实测链路分档（单发 / 定时副本 / 零冗余 / 只探活）与紧凑认证信封，属传输层策略，只进 G5、不进模拟层。大厅与对局分层（发现 / 房间 / 花名册 vs 命令流）同理进 G5。

## 与既有清单的接口

- G5（传输面）：补三条候选——大厅 / 对局分层、中继排序形态（候选主形）、自适应冗余策略格。
- G6（同步面）：补四条候选——延迟参数的全网同步变更与锚定窗、心跳二合一（计数 + 校验和）、开局指纹握手形态、快照重同步预留条目；另加一条校验豁免窗（开局 / 读档后 N 帧不比对，防初始化噪声误判）。
- 物理预测接口：红警 lockstep 的确定性模拟与物理座的「多未来预演」共用同一确定性底座；本节不改变物理座既有口径，只登记互锁关系。

- 只学行为与组织：本节的每条机制都以我方复述落字，证据以仓名 + 文件路径索引回本地参考区；**不取 GPL 代码进 slaengine，引擎保持 clean-room**。GPL 材料仅在本地参考区研读，不入仓、不随仓分发。
