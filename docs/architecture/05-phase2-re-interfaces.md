# 05 Warcraft 阶段二接口预留

阶段二 = Warcraft 支线对原版 24 件核心二进制（Game.dll / Storm.dll
/ War3.exe × 1.20e–1.27a 八个版本包）的系统逆向，产出**原版数据
格式与协议的真规格**。本线开工时（2026-11-08）阶段二仅完成版本
包清单与指纹入账，**尚无结论产出**。本文件的任务是把接入面先
定下来：规格到达时有槽可入，且任何先行实现（按 OpenRealm 行为
写的导入器）都不会被误冻结为规格。

## 5.1 规格槽（两类，落点预留）

| 槽 | 内容 | 预留落点 | 成文要求 |
|---|---|---|---|
| 格式规格槽 | MPQ 归档、地图（.w3x/.w3m 及内部件）、模型（.mdx/.mdl）、贴图（.blp）等格式的版本化规格 | 仓内 `docs/specs/warcraft-formats/`（阶段二首批规格到达时建目录，本集不预建空目录） | 每份规格带：版本矩阵头、四件套证据等级、与 OpenRealm 的差异栏（见 5.2） |
| 协议规格槽 | 局域网会话/建房/同步、战网式协议中阶段二覆盖的部分 | 仓内 `docs/specs/warcraft-protocol/`（同上） | 同上；另带状态机图与数据报布局表（形态参考 04 中 OpenRealm 的头部契约例，但内容只许来自逆向证据） |

版本矩阵头（强制）：横轴 = 版本包（1.20e / 1.21 / 1.24 / 1.26 /
1.27a 等以阶段二实际枚举为准），纵轴 = 二进制件（Game.dll /
Storm.dll / War3.exe），每格标该结论的出处件与证据等级。

证据等级（四级，逐条标注）：**实测**（原版客户端行为复现）/
**反编译**（DLL 代码还原）/**对照**（与 OpenRealm 行为比对一致
或相异）/**推断**（未证，须明标）。推断级条目不得被实现当作
契约消费。

## 5.2 权威序（不可倒置）

```
阶段二规格（实测/反编译级） > 我方实测 > OpenRealm 行为（对照级参考）
```

- 规格与 OpenRealm 行为相异时：**规格胜**，导入器按规格修正，
  差异登记进该规格的差异栏与 04 清单。
- 规格未覆盖处：导入器可暂按 OpenRealm 行为实现，但该部分 API
  标注 `provisional`（见 5.3），不得被上层当作稳定契约引用。

## 5.3 接入面形态（规格到达前的接口预留）

1. **读者 API 先行冻结、解析内部可换**：导入族对上只暴露读者
   契约（07 §7.2：开归档→列条目→读条目；读地图→场景描述符），
   契约以**数据形状**定义，不以任何现行解析实现的行为定义。
   阶段二规格到达后换解析内部，上层（sla_asset 消费者）零改动。
2. **provisional 标记纪律**：凡按 OpenRealm 行为先行实现的解析
   路径，在其模块头与本集登记表标注 provisional + 依据条目；
   规格 v1 覆盖该面后逐项摘除标记，摘除须有对照语料（5.4）
   通过记录。
3. **场景语义汇合点唯一**：Warcraft 地图导入的终点与 SAX3D 资产
   同形——导入产物汇入 sla_asset 的中间产物面（PLAN C1 的
   AssetScene 形态），再经 C2 生成实体。Warcraft 域特有语义
   （触发器、JASS 脚本面等）在中间产物中以**具名扩展段**承载，
   不污染通用面；其运行时解释器是否立项，候阶段二规格与主
   会话裁定（本集不预设）。

## 5.4 一致性语料槽

预留落点：导入族 crate 内的 `conformance/`（随分叉 N1 的座次
裁定一并定）。纪律：语料只许**自制/合成资产**（用户游戏文件
永不入仓——阶段一数据红线，本集继承）；每条语料 = 资产 +
期望解析摘要（条目表/场景描述符摘要），规格修订时语料期望值
随规格版本号更新，旧值留档可比。

## 5.5 与阶段一的关系

阶段一（网页可玩：OpenRealm wasm + 用户 MPQ 浏览器本地导入）
是**验证性里程碑**，其服务形态（OPFS 本地导入）同时证明了
「运行时解析用户归档」是真实需求——此需求是 07 分叉 N1 的
关键约束（导入族须有运行时形态，不能只有离线工具形态）。
阶段一产物不进 slaengine 仓（已发布于 Warcraf 仓），本集只
引用其结论。
